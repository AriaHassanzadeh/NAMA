# مرحلهٔ ۲ — ورود منظومه‌ای، سؤال‌های پروژه و Home

بعد از موفقیت مرحلهٔ ۱، این مرحله را کامل اجرا کن. ابتدا `AGENTS.md`، `docs/STATUS.md`، `docs/USER-FLOW.md` و `docs/DESIGN.md` را بخوان. پیش‌نیازهای سالم مرحلهٔ قبل را دوباره نساز.

مرجع اصلی طراحی `reference/NAMA-Analyze-Design.html` و نسخهٔ خوانای آن `reference/demo/` است. مرجع به‌روز با منظومه شروع می‌شود؛ Home همان طراحی فعلی Analyze است که بعد از سه سؤال نمایش داده می‌شود.

1. مسیرهای واقعی Next.js برای `/`، `/start/idea`، `/start/customer`، `/start/goal` و `/workspace/home` بساز. پوستهٔ workspace روی صفحهٔ منظومه و سؤال‌ها نباشد.
2. منظومهٔ قبلی با لوگوی قرمز مرکزی، آیکون‌های رسانه در مدار، ستاره‌های کمرنگ، توقف حرکت و رعایت reduced motion را به کامپوننت‌های React تبدیل کن. سه‌بعدی‌سازی یا زاویهٔ تازه اضافه نکن.
3. سؤال‌های ایده، مشتری و هدف را یکی‌یکی مطابق مرجع بساز. مثال‌ها، انتخاب‌ها، فرم، بازگشت، پیشرفت، اعتبارسنجی، Enter/Shift+Enter و بازیابی draft بعد از رفرش کار کنند. URL حاوی متن پاسخ‌ها نباشد.
4. بعد از سؤال سوم به Home فعلی برو. Home شامل سایدبار راست، هدر، معرفی مرکزی، کارت‌ها، بنرها، منتخب‌های روز و تب‌های Ads/Products/Shops باشد. UI پروژه و فرم‌های مشترک را کامپوننت‌بندی کن؛ iframe یا سرو کردن دموی vanilla جای برنامهٔ React را نگیرد.
5. در این مرحله داده‌های نمایشی تایپ‌شده برای Home و draft محلی مجازند. مرز موقت را روشن نگه دار تا API و ذخیرهٔ سمت Django در مراحل مربوط اضافه شوند. برای بخش‌های هنوز پیاده‌نشده مسیر جعلی یا دادهٔ زندهٔ ساختگی نساز.
6. تکمیل سؤال‌ها و بازگشت برای ویرایش، نام دستی فضای کار را بی‌دلیل عوض نکند. پاسخ‌ها از پروفایل پروژه قابل مشاهده باشند.
7. فرم‌ها و گزینه‌ها focus و label مناسب داشته باشند. ورودی‌ها و سایدبار در عرض موبایل با هم تداخل نکنند و کل صفحه اسکرول افقی نداشته باشد.
8. بررسی‌های مرتبط و مقایسهٔ تصویری با مرجع را انجام بده. جریان از منظومه تا Home، اعتبارسنجی، back/reload، تغییر تم و کاهش حرکت را بررسی کن. `docs/STATUS.md` را با نتیجهٔ واقعی به‌روز کن و فعلاً مرحلهٔ بعد را شروع نکن.
